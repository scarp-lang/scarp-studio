# Scarp Studio — Windows 11 manual acceptance (development candidate)

This is a **manual verification worksheet** for the full IDE candidate consolidated in **[draft PR #82 targeting protected main](https://github.com/scarp-lang/scarp-studio/pull/82)**. It contains the earlier integration [#55](https://github.com/scarp-lang/scarp-studio/pull/55) and newer compiler, Auto Save, source-safety and Settings drafts through #81. It is not evidence that any GUI check passed. Mark each test **PASS**, **FAIL**, or **NOT RUN**, recording the build SHA and evidence before considering a merge or release.

## Test environment and provenance

- Windows 11 x64, current WebView2 runtime; use a disposable test account or virtual machine if available.
- Download the exact-head Windows executable/unsigned NSIS **candidate from the successful workflow run for the exact commit being tested** (the exact **draft PR #82 head**), not an older stacked-PR build or the published alpha.2 release. Extract both artifact ZIPs into a **new dedicated real directory** and place exactly three regular files at its top level: one `scarp-studio.exe`, one `*-setup.exe`, and the `SHA256SUMS.txt` from the same workflow run. Do not place links, nested extraction folders or extra hidden directories in the candidate directory. Before launching either binary, run the repo's offline validator:
  `pwsh -File scripts/verify-windows-artifacts.ps1 -ArtifactDirectory 'C:\\ScarpStudioAcceptance\\artifacts' -SourceCommit '<exact 40-digit commit SHA>' -RunUrl 'https://github.com/scarp-lang/scarp-studio/actions/runs/<exact run ID>'`.
  This checks for missing, duplicate and modified artifacts, but **cannot prove** that a manually supplied run URL or manifest is genuine; verify provenance in GitHub first. Record the exact run URL, commit and results.
- Download the separate `scarp-studio-windows-provenance` artifact when available. Compare its source commit, tree, run attempt and two executable hashes against the exact run and checksum manifest. Keep the JSON report outside the three-file verification directory; it is CI metadata, not a digital signature.
- Record: Scarp Studio source commit, CI run URL, candidate exe SHA-256, installer SHA-256, Windows build, and any code signing information. An unsigned installer is **not** a stable release. Respect Windows security warnings; investigate them rather than bypassing device protection.
- Obtain the official Scarp `v0.0.6-alpha.20` Windows compiler separately from its [GitHub release](https://github.com/scarp-lang/scarp/releases/tag/v0.0.6-alpha.20) and verify the Windows ZIP archive SHA-256 against its published GitHub release-asset digest:
  `68a5ee47f24e2e36dd7fb1fcc6257feaea291d801048f7866bff1a7e4994aca2`. The installer and compiler archives are distinct files; never compare their hashes interchangeably.
- Check `scarp.exe --version` reports `scarp 0.0.6-alpha.20`. Scarp Studio may automatically **detect** the compiler, but must require explicit trust confirmation of its **exact path** before executing even a version probe; the Download action opens the official ZIP **only on click**, without installing or launching any found executable automatically. Automated CI also checks alpha.10–alpha.15 backwards compatibility, but this manual pass is against alpha.20. CI retains separate alpha.17, alpha.18 and alpha.19 compatibility gates.
- Use only disposable `.srp` files in a test directory, e.g. `C:\\ScarpStudioAcceptance`; keep backups of any data you care about. Never test overwrite handling using real projects.

A ready-to-run [Windows GUI smoke suite](../qa/windows/README.md) contains
real `.srp` files for Run/Verify, fixed arrays, preloaded boolean input and
an intentionally invalid diagnostic. The same source examples are executed
by exact-head Windows CI against the SHA-pinned official alpha.20 compiler (with separate backwards-compatibility checks for alpha.17, alpha.18 and alpha.19).
The optional [manual report helper](../scripts/windows-acceptance-report.mjs) generates all case IDs as NOT RUN and binds evidence to the CI provenance and this worksheet hash. See the [verification plan](next-pre-release.md) for commands. A complete report still requires human review.

**CI only establishes CLI compatibility; mark GUI cases PASS only after
actually testing the Studio desktop build.**
