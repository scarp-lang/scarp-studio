# Scarp Studio

**Scarp Studio** is an Apache-2.0 desktop IDE for the **Scarp programming language only** (`.srp`). It is built with Tauri 2, Rust, React/TypeScript and Monaco Editor, with Windows 11 as the initial target.

## Published version vs. development work

- **Published:** [`v0.0.1-alpha.2`](https://github.com/scarp-lang/scarp-studio/releases/tag/v0.0.1-alpha.2), released 2026-11-12. This is an **experimental, unsigned Windows x64 editor-only pre-release**; it does *not* ship native Scarp Run/Verify, structured diagnostics or full project tools. Interactive Windows 11 acceptance is still incomplete. Use disposable sources and back up your files.
- **Unreleased development:** the complete compiler-integrated IDE is under review as the consolidated **[main-targeted draft PR #82](https://github.com/scarp-lang/scarp-studio/pull/82)**, which includes the original [integration #55](https://github.com/scarp-lang/scarp-studio/pull/55), all subsequent release-hardening changes and recent safety drafts [#76–#81](https://github.com/scarp-lang/scarp-studio/pull/81). This is an **unsigned Windows testing candidate**, not a published or merged pre-release; previously published alpha.2 remains editor-only.
- **Next candidate:** the source package identifies the development target as `0.0.2-alpha.1`, but a version string in source is **not** a published release or approval to publish one.

## Features in the current development branch (not in alpha.2)

- Scarp-only Monaco editing, conservative syntax highlighting, hover, completion snippets, bounded `funcra` / `record` / `variant` declaration outline, starter programs, multiple tabs and dirty-state preservation. The source-matched `qa/windows/08-declaration-outline.srp` exercises the same syntax in actual official compiler Verify/Run smoke checks across alpha.17–alpha.19. The outline and Monaco document symbols distinguish functions, structs and tagged variants, including public declarations, without scanning arbitrary files. The Examples menu now contains **While, Break and Continue** and **Nested Repeat and While** starters, each embedded from the exact checked-in `.srp` QA fixture rather than a separately maintained copy. Windows CI runs both with independently SHA-256-pinned compiler versions; real GUI acceptance C26/E53 is still pending. Windows CI runs both with independently SHA-256-pinned compiler versions; real GUI acceptance C26 is still pending.
- **Current-main editor safety retained:** locally validated/persisted font size, tab size and word wrap; live Save As collision guards; serialized native confirmation dialogs; 4 MiB UTF-8 source limits and selected-folder file membership restrictions.
- **Save All (integrated draft):** Ctrl+Alt+S, toolbar and command palette save modified Scarp tabs in sequence, preserving newer edits and stopping on cancellation, external modifications or path collisions. The native Save As response and asynchronous pre-write disk checks are also guarded against changed or closed source snapshots: an outdated save intent cannot write captured old bytes; Save All still refreshes each later item before its turn. It never auto-runs code. **Post-write read-back (unreleased draft):** after each Save/Save As, a 4 MiB-bounded UTF-8 re-read confirms the exact bytes that Studio wrote before marking a tab saved or proceeding to the next Save All item. If the destination is modified, missing, unreadable or oversized, Studio reports an uncertain/failed save and preserves dirty buffer state; this is a best-effort check, not an atomic compare-and-swap or overwrite guarantee.
- **Auto Save (new integration draft):** opt-in (off by default) and persisted locally, with 1/3/5-second inactivity delays. Saves only named dirty `.srp` files, including inactive tabs; it never opens Save As. Auto Save uses existing external-change comparisons, bounded post-write read-back, per-tab revision guards and bounded retry scheduling, and pauses during compiler operations and native file dialogs. The setting is exposed through the main Settings navigation, Ctrl+, and status bar.
- **Keyboard-accessible document tabs (unreleased draft):** open source tabs now use roving focus and ArrowLeft/ArrowRight/Home/End navigation, with Enter/Space activation and an editor tabpanel relationship. Close buttons do not forward navigation keystrokes to their parent tab. Reducer-independent navigation tests and Windows case E41 cover the intended behavior; GUI acceptance remains pending.
- **Visual editor preferences (new integration draft):** Settings now includes optional Monaco code minimap and visible spaces/tabs. Both are off by default, respond without saving or running sources, persist locally with strict boolean validation, and remain compatible with earlier stored preferences. Restore defaults resets them. Windows acceptance E50 remains NOT RUN.
- **Restore all Studio Settings defaults (new draft):** the Settings reset button now resets font size, tab width, word wrap, minimap and whitespace visibility **and** turns Auto Save off, returning the delay to 3 seconds. It synchronously revokes queued Auto Save writes before the native pre-write check, instead of leaving background disk writes enabled after a reset. Covered by unit tests and Windows case E37.
- **Version-aware compiler discovery (new draft):** when multiple Scarp compiler ZIPs are extracted into Downloads or installed in Scarp program folders, the bounded non-executing scan prioritizes numeric version-shaped folder names (e.g. alpha.18 ahead of alpha.9) before the four-candidates-per-root budget is exhausted. Names are hints, not proof of authenticity: the exact binary path still needs explicit user approval and an actual native version probe. Rust tests cover numeric prereleases and multiple extracted versions; Windows GUI check C24 is pending.
- **Crowded Downloads compiler discovery (new draft):** bounded 4096-name lookahead prioritizes Scarp-named extraction folders ahead of unrelated downloads while keeping the existing 512-entry per-root processing cap. No candidate is executed by scanning; a regression test includes over 600 unrelated files. Windows case C23 remains manual.
- **Downloads compiler discovery priority (new draft):** the bounded native scan visits Scarp-named extracted Downloads folders immediately after standard installed locations and **before unbounded PATH entries**. This prevents a crowded SDK PATH from exhausting the 128-root/4096-entry search budget before reaching an official extracted compiler. Discovery remains non-executing and per-session compiler trust remains mandatory; Rust regression tests cover the previous starvation case.
- **Replace All review protection (new draft):** confirmed replacements remain **buffer-only** even with Auto Save enabled. Affected named source snapshots are held until the user explicitly Saves, Undoes, closes, or edits them again; unrelated files continue to Auto Save. Enabling Auto Save later cannot silently persist previously unreviewed Replace All changes. Disabling Auto Save while a write is still awaiting its preflight comparison prevents an unstarted write; native verified write/read-back still governs any already-finished write. Covered by regression tests and Windows checks E33–E36.
- **Safe tab identity after Save As (new draft):** moving an open A.srp tab to B.srp keeps the original tab stable; reopening the still-existing A.srp now allocates a distinct editor ID. Saving, editing or closing reopened A must never affect moved B. Includes regression tests and Windows acceptance case E32.
- **Compare with Disk (unreleased draft):** an explicit, read-only comparison of a saved Scarp source's last loaded/saved snapshot, current editor buffer and currently readable disk bytes. A bounded 4 MiB single-handle read distinguishes unchanged sources, external-only edits, simultaneous local/disk conflicts and files whose disk bytes now match the current buffer. Small Unicode-safe excerpts and first differing line help decide between Reload and Save As; the review never modifies, merges or approves overwrites, and stale native reads cannot publish against a changed editor session. Windows acceptance E43 remains NOT RUN.
- **Reload from Disk (integrated draft):** toolbar and Commands palette explicitly refresh a saved .srp tab after external edits. A dirty tab requires discard confirmation; tab switches and concurrent edits cancel stale reloads. This feature never auto-executes code.
- **Native Open dialog safety:** selecting an already-open .srp tab reuses its unsaved buffer without reading a moved, missing or externally modified file; new reads are rejected if the active tab switches **or its contents change** before completion. Save and Ctrl+W choose their targets from the latest synchronous editor state. Monotonic per-tab edit revisions reject A→B→A (ABA) races during close, Reload, Replace All/Undo, and search navigation.
- **Alpha.11 editor support:** exact `decimal` type highlighting, checked base-10 conversion/rounding/formatting help, `input_decimal` assistance and two opt-in decimal starter examples. These require a separately installed official Scarp compiler v0.0.6-alpha.11+ to run.
- **Alpha.12 editor support (unreleased draft):** syntax highlighting and completion/hover assistance for typed records, variants, exhaustive `match on`, concrete `option<T>` / `result<T,E>`, immutable `list<T>` and deterministic `map<K,V>` operations; four additional opt-in starters. These require a separately selected official [Scarp v0.0.6-alpha.12](https://github.com/scarp-lang/scarp/releases/tag/v0.0.6-alpha.12) interpreter and are not supported by older compiler executables or experimental native aggregate backends.

The new alpha.13 cache and workspace-generation functions are **Rust embedding APIs**, not new desktop CLI features; Studio does not claim to expose them.
- **Alpha.14 official compiler compatibility (unreleased draft):** an additional exact-hash-pinned Windows CI check verifies the published alpha.14 CLI version, valid source Verify/Run, malformed-source JSON diagnostic coordinate schema and Studio's native process service. ## Develop and test (Windows 11)

Install Node.js 22+, Rust stable with the MSVC toolchain, Visual Studio C++ Build Tools and the [Tauri 2 Windows prerequisites](https://v2.tauri.app/start/prerequisites/). Then run:

```powershell
npm ci
npm run typecheck
npm test
npm run tauri dev
```

For local Rust validation and a development executable:

```powershell
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo check --locked --manifest-path src-tauri/Cargo.toml
cargo test --locked --manifest-path src-tauri/Cargo.toml --lib
npm run tauri build -- --no-bundle
```

Pull-request CI tests separately SHA-256-pinned official Scarp alpha.10–alpha.15, alpha.17, alpha.18, alpha.19 and alpha.20 compiler archives, builds a Windows executable and an unsigned NSIS installer **candidate**, and uploads checksums. An offline PowerShell verifier (`scripts/verify-windows-artifacts.ps1`) checks both artifacts against their exact-run checksum manifest; CI also tests that a tampered executable is rejected. This does not execute the binaries, prove remote provenance by itself, or replace Windows GUI acceptance.
- **Strict candidate-folder contents (unreleased draft):** Windows SHA-256 acceptance now rejects *any* extra file (including hidden/system files) in the dedicated candidate folder, including a hidden second old installer; the automated workflow tests this rejection separately from checksum tampering. Only the exact-run executable, its NSIS setup and SHA256SUMS manifest are permitted as regular files at the candidate-folder root; empty, hidden or nested directories and linked files are rejected.

For repeatable Windows GUI verification, see the [Windows 11 acceptance matrix](docs/windows-11-acceptance.md). It records actual GUI outcomes separately from automated CI; no release is authorized by that document.

- **Go to Declaration (Ctrl+Shift+O):** search the current Scarp buffer's function, record and variant outline; keyboard or mouse navigation, no implicit file reads or execution.

- **Local Go to Definition (F12 / Ctrl+click):** conservative same-file lookup of uniquely named unqualified function calls. Imported symbols, ambiguous names and oversized sources are intentionally not resolved; use Verify for compiler validation.

- **Local parameter hints (Ctrl+Shift+Space):** declared function parameter names and types, active argument tracking for nested and multiline calls; editor-only, no imported symbol resolution.

- **Local function autocomplete:** typed declaration names and parameter labels, case-sensitive prefix matching, unique names only, and identifier-only insertion to preserve existing call syntax.

- **Adjustable compiler output:** Ctrl+J collapse/show, expand/restore, separate setup and input controls, independent scroll regions and always-visible Run/Verify/Stop.
